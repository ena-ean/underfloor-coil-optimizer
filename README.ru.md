# Калькулятор бухт тёплого пола

[![CI](https://github.com/ena-ean/underfloor-coil-optimizer/actions/workflows/ci.yml/badge.svg)](https://github.com/ena-ean/underfloor-coil-optimizer/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Раскладывает контуры тёплого пола по бухтам трубки (50–600 м) так, чтобы
остатки — а по желанию и деньги — были минимальными. Работает целиком в
браузере: без бэкенда, регистрации и трекинга.

## Зачем

Сантехник выписывает 19 петель (≈ 1 300 м трубки) и покупает «бухту на контур» —
это 3 800 м вместо 1 350 м. Простое суммирование длин тоже не спасает: размеры
бухт фиксированы, а перебирать 2ⁿ комбинаций вручную невозможно. Калькулятор
решает задачу упаковки корректно и показывает, насколько результат далёк от
теоретического минимума.

## Возможности

- **Две цели** — минимум метров закупки или минимум денег (цена за метр может
  отличаться для разных размеров бухт).
- **Доказуемое качество** — нижняя граница закупки и разрыв с ней: если разрыв
  равен нулю, решение оптимально по определению. До 13 контуров работает точный
  поиск (branch and bound).
- **Пересчёт на лету** при вводе, спецификация закупки, процент заполнения
  каждой бухты и распределение «контур → бухта».
- **Экономия** относительно наивной закупки «бухта на контур».
- **Вставка из Excel** — скопируйте колонку длин и вставьте в список контуров.
- **Экспорт** — печать/PDF, CSV для Excel, автономный HTML-отчёт.
- **Русский и английский**, старт на языке системы, тёмная тема, клавиатура,
  адаптивная вёрстка.
- **Офлайн** — всё считается на клиенте и хранится в `localStorage` под
  версионированным ключом.

## Как работает раскладка

1. Все длины переводятся в целые **миллиметры** — сравнения никогда не зависят
   от погрешности float.
2. **Эвристика** — best-fit с заглядыванием на шаг вперёд (три порядка входа) и
   локальный поиск по четырём окрестностям: перенос петли, обмен двух петель,
   объединение двух бухт, разбиение бухты. Каждое принятое изменение строго
   улучшает оценку.
3. **Точный решатель** (≤ 13 контуров, лимит узлов и времени) — branch and bound:
   бухты строятся по одной, самая длинная нераспределённая петля обязана попасть
   в создаваемую бухту, что делает перебор каноническим. Оставшаяся длина даёт
   нижнюю границу для отсечения.
4. **Нижняя граница** — любая закупка есть сумма размеров бухт, то есть кратна
   их наибольшему общему делителю: `ceil(всего / gcd) × gcd`. Нулевой разрыв
   доказывает оптимальность даже без точного решателя.

Оценка лексикографическая: деньги (если включена цель «стоимость») → длина
закупки → количество бухт.

## Структура

```
src/
  app/                 layout, page, manifest, иконка, /api/health
  components/
    calculator/        редактор контуров, параметры, сводка, результат, бухты
    layout/            шапка, подвал
    ui/                только те примитивы shadcn/ui, что реально используются
  lib/
    algorithm/         типы, модель стоимости, эвристика, точный решатель, API
    i18n/              словари (ru, en), провайдер, определение языка
    report/            спецификация, CSV, HTML-отчёт, скачивание файла
    calculator-state   хранилище (useSyncExternalStore) + reducer
tests/                 тесты упаковки и отчётов
docs/                  рабочий журнал, скриншоты
```

## Тесты

```bash
npm run test
```

Проверяются эталонный случай (19 контуров по 64/74 м → 7 бухт по 200 м, 106 м
остатка, оптимальность доказана), сравнение с полным перебором на малых
примерах, цель «стоимость», ошибки валидации, нижняя граница, CSV и разбор
вставки из буфера.

## Настройки

Переменные окружения не нужны. `PORT` (по умолчанию `3000`) учитывают
`next start`, standalone-сервер и `docker compose`. См. `.env.example`.
